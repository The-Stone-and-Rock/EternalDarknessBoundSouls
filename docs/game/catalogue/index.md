# The catalogue: every level, room and region with what it runs

Generated by `python -I tools/ed/ed.py catalogue` (tools/ed/catalogue.py) from build/ed-db: the disc and the kit's readers, no game run. A level's page lists each room's own scripts, its doors, and every region's scripts call by call with the tests that guard each call; camera-only scripts are summed up per room. The TSV beside each page has every row. What this can't know: story gates beyond the literal tests shown (a flag set elsewhere, a variable from another script), timing (what runs a frame later, what waits), anything only seen on screen, and calls whose argument is a variable. The tests shown are the nearest ones in the script, not the whole path.

## The known co-op patterns

Each row of the catalogue is tagged with the known patterns it shows (TSV column `patterns`). They are counted in units, per script (a level's copy) or per distinct call (the call and its literal arguments, over every level), so a long script or a repeated call counts once. A unit is covered (a fix the kit can see applies), uncovered (none it can see), or n/a (whether it's covered is a run-time fact). The fix is what already exists for that pattern in runtime/host/hle.c, with the commit that added it. `ed patterns KEY` lists the uncovered units with where each is met; patterns.json beside this file has them all.

"bracket": covered only when player 2's run goes through the bracket around their own runs (coop_use_start: their player, room, zones' words and script words in), as a region's own enter/leave/stay script does for whoever crosses it; "uncovered" for those words means the run is outside it: a region's other_* script, or a script run next.

Run-time only, no check from the disc: held buttons reaching the world as new presses (coop-failed-attempts.md: the stayer's kept exit B); host state a save state doesn't carry (states saved apart: coop_state_loaded); one render resource per frame (the fade quad: g_fade_mover; the shared vertex buffer's flip, r13-21824).


Co-op flagged rows by word, over every level: the room in play 615, the script words 173, the room in play (in an input mode's own code) 133, the look being set up 93, the magick record 2.
A row is flagged when its call branches on a per-player word within one call and no live host hook sits on the function holding that compare. It's a place to look, not a bug found.

Statuses in the co-op columns: **hooked** (a live host hook on the script function or the function holding the compare: logs, traces, hooks that lose their slot and hooks that act for one caller only don't count), **keyed** (a table looked up by an id the caller passes), **per run** (written for every script run, whoever's), **routed** (an input mode's pad while the mode is player 2's: coop_input_mode_start), **helper** (tools/ed/player_data.tsv names a host helper that puts player 2's in), **one per game** (no copy of player 2's).

The two biggest, the room in play and the script words, are put in for player 2 by the brackets around their own runs (coop_use_start, coop_run_script's first block, coop_stay_room_in with coop_states_swap). A flag there matters where a run happens outside those brackets: a region's other_enter script, a script queued for a later frame, a timer, or a room's arrival script run for player 2 with player 1 still the character. Whether a bracket is in force on a given run is a run-time fact the catalogue can't see.
