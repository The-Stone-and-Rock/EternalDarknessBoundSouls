# Kit groundwork: the tables behind the catalogue (read 2026-11-16)

Read from the code by a workflow (one reader per table, then a refuter per reader), read only, no game run. Each field
names the instruction that reads it. "proved": read from code; "pattern": a value pattern checked over every row;
"unknown": not traced. The refuters' corrections follow each section and override the text above them.
Used by tools/ed/facts/cinematics.py, tools/ed/facts/hooks.py and build_db.one_room (arrival and leave scripts).

Notes:
- Base references: 33 sites build 0x80242150 as lis -32732 / addi 8528, then index with rlwinm n,5 (n*32). There are 2 more 8528 stores at 0x80100F60 and 0x80100F78, but they use lis -32717 and are unrelated. Searching folded displacements 8529-8559 found nothing from this base. A reader that saves a record pointer and dereferences it later would not show up in this search.
- Cinematic name and files: no per-cinematic name string exists in the dol. Each film has three files. The model/actor pack is /levels/level{+16:02}/cin{+17:04}.bin (format 0x8023BDD4, used by 0x80007FA0). The spool data is /levels/level{+16:02}/cin{+0:04} (format 0x80253034, used by the loader case 0x80153540 in 0x801531CC). The soundtrack is the stream table 0x8024C8E0[+10] (166 x 32-byte path strings: /levels/levelNN/act*.aud, no_audio.aud at 60, /audio/music/*.adp). +0 and +17 often differ: row 2 has +0 = 0 and +17 = 2.
- The record +4 is an s32 holding the row number, i.e. the task's '+6 = row'. +0..+3 are the +0 s16 and a zero halfword. The note in docs/game/systems/players.md ('+0 high half the cin file', '+16 top byte the level folder, next byte the .bin') matches this layout. The .bin number is +17, not +0.
- 0x803162C0 block fields that gate these readers, named by address only: +474 the cinematic number, +464 the end-script override, +476 a mode byte (nonzero takes the follow-on path at 0x80026F8C and skips most loads), +480 the alignment copy, +484 the follow-on-pending flag, +456 a frame or state count. Byte 0x80308A84 gates the +22 paths. Its meaning is not traced here; primitives' ed89 entry links it to the game-end path.
- 0x80022328(1) on +22 rows at the film's end (0x800267EC) means game mode 5 with how=1. What that does there was not traced.
- ed264 (0x80012800) picks the seen-flag block from +18, while play (0x800262DC) and EDSetAll (0x80051AD4) pick it from max(+19,0). These match only where +19 == +18-1. They differ in rows such as 82, 93, 163, 164, 167 and 168 (+18 = 0 with +19 = 1, 4, 2, 0, 4, 4), so for those rows ed264 sets the flag in a different block. This is an observation from the code, not checked by running.
