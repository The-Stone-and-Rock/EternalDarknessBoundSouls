
######## gamedraw
The room is drawn in two passes per frame, both from the draw function 0x800080E4: the opaque pass 0x801E851C (bl at 0x80008118) calls 0x801E75B4(3) then 0x801E75B4(2), and the translucent pass 0x801E85E0 (bl at 0x80008140) calls 0x801E73D4(3) then 0x801E73D4(2); section 3 is the OTHER slot's record (table +4), section 2 the current's (0x80155130). Neither section function loads a position matrix: the room's vertex formats carry no PNMTXIDX (0x801E16D0 does GXClearVtxDesc then POS/NBT|NRM/TEX only), so the room draws with the CURRENT matrix, which the room code sets to 27 (0x801E5420 inside the list builder, 0x801E866C in the translucent pass). Index 27 holds the camera matrix 0x8060248C, loaded by exactly two sites: 0x801E4DC8 (in 0x801E4BDC, the camera build; run in the update at 0x8000843C via 0x801E1164 BEFORE the opaque pass, and again at 0x80008128 via 0x801E9728) and 0x801E85F8 (the translucent pass). 0x801E7350 loads only a texture matrix (index 48, 2x4) from the camera's inverse-transpose. The refuter's "camera loaded into 27 at 0x801E85E0-0x801E85F8" is right about the address but it is the translucent pass's own function, not inside 0x801E851C. The per-view exclusion must therefore be: at each section's entry (both 0x801E75B4 and 0x801E73D4, four calls a frame) re-issue a marked copy of the matrix in 27 (mark 0xD2/0xA0+view/0xE5 at +15/+31/+47, honoured by interp.cpp marked_out_of on the draw's posnormalmatrix), and restore the unmarked matrix after section 2, because later draws use 27 without reloading it (0x801F41C8 in fn_801FF9E4 at 0x80008174, 0x801DC450/0x801DC55C, 0x80129BA0, menu code 0x800EBF28..0x800EDAF0). When the other slot holds a room nobody is in (or both players share a room, or the frame is drawn whole) section 3 must be skipped entirely (one mark can exclude only one view). Cleanest shape: an intercept on 0x801E75B4 and 0x801E73D4 that skips or wraps the game's call with hle_guest_call (marked load before, unmarked load after; precedents room_slots_layout and hle_draw_characters). Actors: the game never gates the object draw by room (registration 0x80119B94 and the consumer 0x80119D60 -> 0x8011A278 test only flags), so a per-room rule goes in coop_found_object_draw: object+592 against each view's room, marking out of the view whose player's room differs, only when no found/unseen list matched. The fade quad is the game's own: identity into index 0 at 0x801E7F5C (lr 0x801E7F60), current 0, ortho, whole-screen quad: mark it in notify_GXLoadPosMtxImm by that lr for the non-mover's view. HUD, prompts and words are orthographic draws classified isHud in build_view and never use 27: untouched by the room mark unless 27 is left marked.

## hazards
- A mark left on index 27 after section 2 hides every later draw that uses 27 without reloading it (0x801F41C8 in fn_801FF9E4 at 0x80008174, 0x801DC450/0x801DC55C, 0x80129BA0, 0x801819C4, the menu code 0x800EBF28..0x800EDAF0) from one half: the unmarked matrix must be restored after section 2 of BOTH passes (0x801E75B4 and 0x801E73D4), every frame, including the early-return paths (record 0 or unloaded) if the marked load happened before the call.
- Marking 0x8060248C in place would perturb the low mantissa byte of the camera's translation for the game's own readers (unproject 0x801EB15C via 0x806024BC, physics/camera code at 0x8017xxxx, the lights' PSMTXMultVec, the texture matrix in 0x801E7350); use a host scratch copy.
- hle_guest_call of a section draw runs GXCallDisplayList's HLE continuation inside the call; if the intercept were ever entered while g_display_list_call.active (e.g. from a GXCallDisplayList notify) the list would be dropped with '[gx] nested GXCallDisplayList host continuation'. Enter only at the section function's entry, with a `running` guard so the nested dispatch of the same address passes through.
- hle_guest_call ends the call (ok=false) on any exception other than a syscall (main.c:88-93): a decrementer or VI interrupt landing inside the ~0x51CA0-byte list call would abort the room's draw for that frame. hle_draw_characters survives the same exposure; log and passthrough on !ok.
- Section 3's skip must be total (no GXLoadTlut/texture bank/GXSetArray side effects either) or the game's state for the current slot could differ: 0x801E75B4 stores the current record's +0x813C to r13-21808 and sets/restores the texture bank r13-22132; when section 3 is skipped these happen once instead of twice, which is the N=1 behaviour (table +4 == -1 gives record 0 and the same early path).
- Both players in one room while the other slot still holds a loaded stale room (the game's own hidden frame, a cutscene or menu drawn whole): without the skip, that room is drawn under the live one in both halves (seen as double geometry in the R1 probe); the skip must not depend on coop_stay_apart alone.
- A mark excludes only one view per matrix: an actor in neither player's room cannot be hidden from both by marking; it needs the object draw skipped (an intercept on 0x8011A278 returning early) or a second mark byte value the renderer learns.
- The lights are one grid (0x801E53FC per section loads the same lamps through the same camera; the design keeps player 1's room's grid for both): player 2's room will be lit as player 1's is until a renderer change.
- The frame cost is the second room's draws replayed in every output view (3, or 5 with photo/moments): measure with DOL_INTERP_LOG and [fps] before keeping it (design.md R3).
- 0x801E1BE8 caches the current matrix index in r13-21972 and only sends GXSetCurrentMtx when it changes: the room's per-frame built list (record+296[turn]) carries a SetCurrentMtx(27) only when the cache said otherwise at build time; the host's re-issue of 27's content does not touch the current index, so this is harmless, but any host code that changes the current index must go through the same cache.
- runtime/host/controls.cpp may hold uncommitted test edits; the uncommitted hle.c room_slots/coop_stay code is the base to build on (HEAD 6b2a584 lacks it).

## hazards
- The mark changes the low mantissa byte of the camera's three translation floats (about 1e-5 relative): invisible in the picture, but if the host marks 0x8060248C IN PLACE (as coop_found_mark marks actor matrices in place) the game's own readers of 0x8060248C (0x800D8A88's unproject, the camera tests that copy 0x8060234C..) see the marked bytes; mark a copy instead and load the copy.
- The room's display list is built once (record+0x8148 non-zero -> GXCallDisplayList of record+288) and may itself contain XF matrix loads or a GXSetCurrentMtx; if it loads its own matrix into 27 (or uses another index), the host's re-issue at entry is overwritten or misses. Settle with ED_MATRIX_LOG (hle.c:3300-3345: '[posmtx]' lines carry pn index and, via ball_load's format, lr) plus a gxcore DL decode of one room list; if the list loads 27 itself, the mark must go into the matrix the list reads (the record's own copy) or the dedup breaks.
- If the room draws' current pn matrix is NOT 27 while their vertices carry per-vertex indices (has_pos_mtx_idx), the Vs block (rows of current_pn_matrix) is unmarked and only the XF test catches row 27 — fine for exclusion, but the Vs memo then merges section 3's and section 2's Vs blocks (identical bytes) while the XF blocks differ: still correct (build_view zeroes the XF rows per draw's xf offset), just note that the 'separate blocks' happen in the XF table, not the Vs memo.
- The shadow camera g_sh.view is taken from the frame's FIRST scene draw with has_pos_mtx_idx == 0 (gxcore_draw.cpp:2133-2136): with section 3 drawn first that is the stayer's room's (marked) matrix — the same camera, harmless; but when section 3 answers 0 on some frames and not others, the first draw flips between sections (no visible effect expected; watch [shadow] logs for a cut flag: g_sceneCameraCut).
- A per-command skip must NOT skip in the Real frame's encode (the game's own frame must stay whole for the EFB copies/XFB) and must be cleared after each view (as set_view_shape(1,0) is), or the next output inherits it.
- render_glow_pass and render_character_shadows re-iterate passInfo.commands per replay: the excluded room's collapsed draws cost a little there too; a skip that only touches render_with leaves them (harmless).
- 0x80155130 answering 0 for section 3 makes 0x801E75B4 skip everything, including its texture-state calls (0x801E1B74 at 0x801E76C8/0x801E793C, GXLoadTlut x4 at 0x801E75FC-0x801E762C) — the second section re-issues them, so the picture is unaffected, but the stayer's room disappears from the Real frame on those frames: intended for whole-screen moments, wrong if the intercept fires while the halves are shown.
- split::plan declines a frame when a channel spilled past its staging slice ('past its staging buffer'): two rooms' worth of display lists per frame raise the chance of a spill (verts/uniforms over VertexBufferSize/UniformBufferSize), which would show the Real frame whole (both rooms) for that frame.
