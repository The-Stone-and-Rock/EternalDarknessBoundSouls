The mark path holds. GXLoadPosMtxImm (0x8021FBAC) is notify-only in the host; its recompiled body writes the XF load to the write-gather pipe, which reaches the same ordered gxq byte stream as the HLE'd GXCallDisplayList (append_gx / append(Op::CallDisplayList)), so a guest call from the section function's entry lands before the list. No continuation state is live at that entry, the nested dispatch of a notify-only entry leaves g_hle_passthrough/g_hle_tail_call alone, and coop_found_mark cannot fire on the host's load (lr is the guest-call sentinel). 0x8060248C is the game's row-major 3x4 LookAt matrix (r31 = 0x80602300 + 396; C_MTXLookAt at 0x801E4D58; loaded into 27 at 0x801E4DC8 and 0x801E85F8); +15/+31/+47 are the translation floats' low mantissa bytes and survive the psq_l/psq_st path (except an exactly-0.0f translation, a denormal flush corner coop_found_mark shares). build_view zeroes only the view's copy, the Real output uses the game's uniforms, and push_uniform_memo/s_sharedUploads hash the whole blocks so a one-byte mark difference gives separate Vs and XF blocks. Two corrections: (a) the readers' 'interrupt inside the guest call aborts the draw' hazard is refuted (interrupts are delivered only by interrupt_poll in the main run loop, by redirecting pc, never inside hle_guest_call); (b) an intercept that answers 0 for section 3 without passing through skips notify_room_draw -> room_slots_frame for that frame (hle_dispatch returns before the notify), so the intercept must call room_slots_frame itself.
